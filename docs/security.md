# Проверка безопасности демонстрационного стенда

## Проверенные условия

| Область | Результат |
| --- | --- |
| Гостевой и авторизованный режим | Гостевой запрос профиля возвращает `user: null`. История требует входа и снова возвращает HTTP 401 после выхода. Ошибка входа не раскрывает, какая часть учётных данных неверна. Ответы входа и регистрации содержат только публичные поля пользователя. [API-04](../tests/contracts.api.spec.ts) |
| Изоляция данных | Тесты используют отдельные контексты и временные экземпляры для операций с остатками. В отчётах используются вымышленные имена, пароли и адреса `example.test`. Публичные браузерные smoke-проверки выполняют чтение. [Матрица](coverage.md) |
| Развёртывание | Контейнер магазина запускается без root. Тестовый сброс отключён. Prometheus в контейнере мониторинга слушает loopback. Саморегистрация и анонимный доступ к закрытому разделу Grafana отключены. Публично доступны витрина и дашборд с агрегированными метриками. [Образ магазина](../deploy/Dockerfile.shop) · [Мониторинг](../monitoring/hosted/README.md) |
| Доступ в Grafana | Сквозная проверка получает HTTP 401 от закрытого API, читает панели публичного дашборда и подтверждает поступление метрик после одного синтетического заказа. [Проверка развёртывания](../scripts/check-deployment.mjs) |
| Зависимости и артефакты | При проверке обоих npm lockfile реестр вернул 0 известных находок. На проверенных сборках магазина Trivy не обнаружил известных уязвимостей пакетов на arm64 и amd64. В образе мониторинга на arm64 обнаружены зависимости с 7 уникальными находками уровня High, без Critical. Проверка конфигурации не установила доступность затронутого кода через публичный дашборд. В опубликованных скриншотах и текстах проверены признаки секретов и личных контактов. Распознанные контактные значения относятся к тестовым данным. |

## Результаты ревью исходника

| Приоритет для продакшена | Наблюдение | Что исправить |
| --- | --- | --- |
| P1 | Проверка конфиденциальности отдельного заказа недостаточно строго связывает доступ к заказу аккаунта с активной авторизацией владельца. Источник наблюдения — ревью исходного приложения. | Требовать активную сессию владельца для заказа аккаунта. Для гостевых заказов применять отдельное правило владения. Отзывать сессию при выходе и обновлять идентификатор при входе. |
| P2 | Cookie сессии использует `HttpOnly` и `SameSite=Lax`, но без флага `Secure`. В коллекции сессий отсутствует серверное истечение. В исходном приложении отсутствует ограничение частоты входа и регистрации. | Защитить cookie на HTTPS, ограничить срок и количество активных сессий и добавить ограничения частоты на маршрутах входа и регистрации. |
| P3 | В исходном приложении отсутствует явная политика запрета кэширования ответов с данными аккаунтов и заказов. | Добавить `Cache-Control: no-store` для ответов с персональными данными. |

Результаты относятся к демонстрационному стенду и к указанным локальным сборкам. Публичный стенд предназначен для вымышленных данных. Ревью исходника и проверка зависимостей дополняют сценарные автотесты. Тестирование на проникновение и работа с реальными персональными данными находятся за рамками задания.
