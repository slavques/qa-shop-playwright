# QA магазина «Лавка»

[![Playwright](https://github.com/slavques/qa-shop-playwright/actions/workflows/playwright.yml/badge.svg)](https://github.com/slavques/qa-shop-playwright/actions/workflows/playwright.yml)

Автотесты Playwright на TypeScript для исходного магазина из [тестового задания](https://qa-test.g-profile.ru/). Набор проверяет каталог и поиск, корзину, скидки, оформление заказа, регистрацию и вход. Docker Compose поднимает исходный магазин, Prometheus и Grafana.

## Публичный стенд

[Витрина магазина](https://lavka-qa-slavques.onrender.com/) · [Дашборд Grafana](https://lavka-monitoring-slavques.onrender.com/public-dashboards/8451f62756b3c4e40274741271c86b14) · [Прогоны CI](https://github.com/slavques/qa-shop-playwright/actions/workflows/playwright.yml)

Grafana открывается без входа. На Render Free первый запрос после простоя может занять около минуты. При перезапуске сбрасываются тестовые заказы и история метрик. Каталог и публичный дашборд восстанавливаются автоматически. Если Grafana уже отвечает, а панель ещё загружается, обновите страницу после завершения запуска. [Ограничения Render Free](https://render.com/docs/free)

Для регистрации и заказа на демонстрационной витрине используйте вымышленные данные. В образе магазина отключён тестовый сброс. CI проверяет, что гостю доступен публичный дашборд, а закрытый API дашборда Grafana и история заказов требуют входа.

## Запуск автотестов

Нужны Node.js 22+ и npm. Распакуйте [архив магазина](https://qa-test.g-profile.ru/download/qa-shop.zip) рядом с репозиторием.

```bash
git clone https://github.com/slavques/qa-shop-playwright.git
cd qa-shop-playwright
npm ci
npm ci --prefix ../qa-shop
npx playwright install chromium firefox webkit
npm run typecheck
PLAYWRIGHT_FULL_MATRIX=1 npx playwright test
npm run report
```

На Linux установите системные зависимости браузеров командой `npx playwright install --with-deps chromium firefox webkit`. Для архива в другом каталоге передайте `SHOP_DIR=/абсолютный/путь/qa-shop`. Если порт `3100` занят, задайте `SHOP_PORT`.

Playwright запускает локальный магазин со свежими данными. Сценарии оформления получают отдельные экземпляры магазина, поэтому остатки изолированы между тестами. Аккаунты и заказы используют синтетические данные. `PLAYWRIGHT_FULL_MATRIX=1` включает полный десктопный регресс в Chromium, Firefox и WebKit, а также сквозные сценарии приёмки в сенсорных профилях Pixel 7 и iPhone 13. `npm test` ограничивает прогон Chromium. С `BASE_URL` выполняются только smoke-тесты без создания аккаунтов или заказов.

`npm run test:api` запускает локальные HTTP-контракты без браузера. В полном прогоне этот проект выполняется один раз.

```bash
BASE_URL=https://lavka-qa-slavques.onrender.com npm run test:smoke
BASE_URL=https://lavka-qa-slavques.onrender.com npm run test:cross-browser
```

При `BASE_URL` готовность `/api/health` проверяется до запуска smoke, в том числе после простоя Render. У тестов автоматические ретраи отключены. Чтобы выполнить каждый сценарий дважды в полной локальной матрице, запустите `PLAYWRIGHT_FULL_MATRIX=1 npx playwright test --repeat-each=2 --workers=4`.

В GitHub Actions архив проверяется по SHA-256, а оба lockfile проходят проверку `npm audit` с порогом `high`. Затем запускаются TypeScript-проверка и все проекты Playwright. Артефакт содержит HTML- и JUnit-отчёты, скриншоты и трассы падений. Отдельная задача проверяет правила Prometheus, запускает образы стенда и подтверждает через публичный дашборд, что метрики тестового заказа дошли до Grafana.

## Что проверено

| Область | Проверки |
| --- | --- |
| Каталог | Поиск, фильтрация, сортировка, карточка и остаток |
| Корзина | Добавление, изменение количества, удаление, очистка и пересчёт |
| Промокоды | `SALE10`, `WELCOME500`, недействительный код и условия скидки |
| Заказ | Самовывоз и курьер, валидация, доставка после скидки, итог и изменение остатка |
| Аккаунт | Регистрация, повторный e-mail, вход, неверный пароль, выход и история заказов |

Подробные сценарии и границы покрытия приведены в [матрице](docs/coverage.md). Проверенные условия и замечания к исходнику приведены в [отчёте по безопасности](docs/security.md).

Playwright учитывает текущие воспроизведения как ожидаемые падения. Если дефект исправят, неожиданное прохождение потребует пересмотреть пометку.

## Мониторинг и развёртывание

Prometheus собирает метрики магазина с `/metrics`. Дашборд показывает доступность сбора, интенсивность запросов, долю HTTP 5xx, p95 задержки, заказы, выручку и остатки. Определения показателей, настройки и команды запуска приведены в [инструкции мониторинга](monitoring/README.md).

Для хостинга с лимитом на два сервиса используйте [образ магазина](deploy/Dockerfile.shop) и [образ мониторинга](monitoring/hosted/README.md). Такой стенд публикует HTTPS-витрину и дашборд Grafana для просмотра.
