# Grafana и Prometheus в одном сервисе

Образ для демонстрационного хостинга с лимитом числа сервисов. Магазин запускается отдельно. Графана слушает HTTP-порт `3000`, Prometheus слушает только loopback внутри контейнера.

| Параметр | Значение |
| --- | --- |
| Контекст сборки | `monitoring` |
| Dockerfile | `monitoring/hosted/Dockerfile` от корня репозитория или `hosted/Dockerfile` от контекста сборки |
| Публичный порт | `3000`, HTTP с завершением TLS у провайдера |
| Проверка готовности | `GET /api/health` |
| `SHOP_METRICS_TARGET` | Имя сервиса магазина и порт, например `shop:3000` |
| `SHOP_METRICS_SCHEME` | `http` для трафика внутри проекта, `https` для сервиса с TLS |
| `GF_SERVER_ROOT_URL` | Публичный HTTPS-адрес Grafana |
| `GF_SECURITY_COOKIE_SECURE` | `true` при внешнем HTTPS |
| `GF_SECURITY_ADMIN_PASSWORD` | Уникальный пароль администратора, хранится в секретах хостинга |
| `GRAFANA_PUBLIC_DASHBOARD_TOKEN` | Постоянное значение из `openssl rand -hex 16` |

Дашборд открывается по `<GF_SERVER_ROOT_URL>/public-dashboards/<GRAFANA_PUBLIC_DASHBOARD_TOKEN>`. При старте контейнер проверяет общую ссылку и создаёт её, если базы Grafana ещё не было. Сохраните значение токена между деплоями, чтобы адрес оставался прежним.

Если хостинг предоставляет постоянный том, подключите его в `/var/lib/grafana` с записью для UID `472`. В томе хранятся база Grafana и история Prometheus. При эфемерном диске история начинается с нуля после замены контейнера. Держите один экземпляр мониторинга для согласованной локальной истории данных.
