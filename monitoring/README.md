# Мониторинг QA Shop

Prometheus опрашивает `shop:3000/metrics` каждые 15 секунд и хранит данные 14 дней.
Grafana автоматически загружает источник данных и дашборд **QA Shop · Мониторинг**.

## Запуск

Выполните из корня репозитория после распаковки исходников магазина.

```bash
export SHOP_DIR=/absolute/path/to/qa-shop
export GRAFANA_ADMIN_PASSWORD="$(openssl rand -hex 24)"
docker compose -f deploy/compose.shop.yml -f monitoring/compose.yml up -d --build
```

Откройте `http://localhost:13000/d/qa-shop-observability` и войдите под именем `admin` с заданным паролем. Значение пароля применяется при первом запуске с пустым томом Grafana. Для постоянного стенда храните его в менеджере секретов.

Для внешнего просмотра направьте HTTPS-прокси на Grafana, задайте `GRAFANA_ROOT_URL` с внешним адресом и `GRAFANA_COOKIE_SECURE=true`. На дашборде выберите **Share → Share externally → Enable external sharing**. Ссылка `/public-dashboards/…` открывает интерактивный дашборд без учётной записи и выполняет только сохранённые запросы панелей. В настройках анонимный вход в саму Grafana выключен. Prometheus доступен внутри сети Compose.

## Как читать дашборд

| Панель | Интерпретация |
| --- | --- |
| Сбор метрик | Результат последнего опроса `/metrics`. При сбое или отсутствии цели индикатор показывает «Недоступно». |
| Трафик API | Запросы в секунду за 5 минут по известным маршрутам API. Статика, `/metrics` и `/api/health` исключены. |
| Доля HTTP 5xx | Серверные ошибки как доля трафика за 5 минут. Пустое значение означает, что недостаточно данных для расчёта. HTTP 4xx видны отдельно. |
| p95 задержки | Приближение по гистограмме Prometheus. При отсутствии запросов значение не рассчитывается. |
| Заказы и сумма | Счётчики оформлений и итоговых сумм с учётом доставки за время работы текущего процесса. После перезапуска отсчёт начинается заново. |
| Сессии, остатки, события | Сессии в памяти, позиции без остатка, добавления в корзину, регистрации и отказы входа помогают сопоставить состояние магазина с трафиком. |

Правила Prometheus отслеживают потерю цели сбора и устойчивый рост HTTP 5xx при достаточном числе запросов. Состояние правил хранится в Prometheus. Канал отправки уведомлений не настроен.

## Проверка конфигурации

```bash
docker run --rm --entrypoint /bin/promtool \
  -v "$PWD/monitoring/prometheus:/rules:ro" \
  prom/prometheus:v3.16.0 check config /rules/prometheus.yml

docker run --rm --entrypoint /bin/promtool \
  -v "$PWD/monitoring/prometheus:/rules:ro" \
  prom/prometheus:v3.16.0 test rules /rules/alerts.test.yml
```

После запуска проверьте `http://localhost:13000/api/health`, затем откройте внешнюю ссылку в приватном окне. Сбор метрик должен быть зелёным. Откройте каталог и подождите два цикла опроса, чтобы появились данные трафика и задержки. Оформления и регистрации выполняйте на демонстрационном экземпляре с вымышленными данными.
